## 4. Missing buttons and screens (by role)

Severity: **H** = would be noticed in a demo or on day one, **M** = expected soon, **L** = nice to have. Full list with file references: `detail/2-ui-and-buttons-audit.md`.

### Merchant (restaurant, mostly on a phone)

- **M:** Orders list has no filter, search, payment status or invoice link. Basket has no "Clear basket", no delivery-address block ("different address?") and no sticky total on phone.
- **M:** "Your usual items" strip, favourites or quick-order for an 800-line catalogue.
- **M:** Account page is read-only: cannot edit contact, phone, delivery notes or add a colleague login.
- **M:** Invoices page has no "you owe £X" summary, no date filter.
- **M:** Order page: no "message us about this order", no print view.
- **L:** "Added" toast has no "View basket" action.

### Admin
- **H: Cannot create an order for a restaurant** (phone and WhatsApp orders are normal in this trade), and the order editor cannot **add a line** or change a sell price.
- **H: Bulk cost / price entry** (see section 2, item 1) and **bulk actions on products** (hide, change category, assign supplier, set VAT).
- **H: Cannot switch off, re-invite or reset the password of restaurant and admin logins** (only supplier logins have the switch). There is no "reset password" for anyone.
- **M:** No CSV/Excel export anywhere except the missing-price list: orders, payments in and out, customers, invoices (the accountant will ask).
- **M:** No customer statement or balance; customer page has no Orders tab; no "view the shop as this restaurant".
- **M:** No print/PDF of an order or a delivery note; no manual status override (a supplier who never clicks Accept leaves the order at "Placed" forever); no change of delivery date.
- **M:** After the first delivery the whole order is locked: no credit note, no fix for a short delivery.
- **M:** "Hold" and "Reject" a customer act at once with no confirmation.
- **M:** Pricing screen has no profit or margin % per size, no select-all, no CSV of fixed prices.
- **M:** Long forms show "Saved." at the top, off screen on a phone; no sort on lists; reminder button hidden on phone.
- **L:** Dashboard has no quick actions (New customer, Record payment) and no search; the "Pricing" menu item just jumps to Customers.

### Supplier
- **M:** Only a logo and a list: no account page, no change-password, no contact-the-office link.
- **M:** No print or packing list; no way to say "cannot supply / short supply / substitute"; no confirmation before "Mark out for delivery".

### Driver (link page on a phone)
- **M:** Address is not a map link; no "could not deliver / report a problem"; no call-the-office button.

### Public site
- **H:** Terms, Privacy, Cookies, Delivery pages and footer links (item 5 above).

## 6. Security and production readiness

No door is open: **0 critical findings**, no way found for a restaurant or supplier to see costs, margins or another customer's data, no secret in the code or its history, and the admin password was never written into the repo. Details and file references: `detail/3-security-and-production-audit.md`.

**Fix soon (High):**
1. **Admin account has no second factor.** Anyone with the admin password can change the bank details customers pay into. Rotate the password you typed in chat now, turn on TOTP two-factor in Supabase, and I will require it for admin.
2. Invoices charging VAT without a seller VAT number (same as item 6 above).
3. No emails (same as item 3).

**Fix before launch (Medium):**
- Login cookies are readable by scripts and last 400 days; no Content-Security-Policy header. Easy hardening.
- Anyone can call the Supabase sign-up and login endpoints directly, skipping the app's rate limits and password rules. Enable captcha and a 10-character minimum in Supabase, and turn on leaked-password protection (the Supabase advisor flags it today).
- The rate limiter lets everyone through if it errors or if the server key is missing (previews have no key).
- Email links are used up on the first click, so company mail scanners will break invitation and reset links. Needs a "Continue" button page.
- **The repository is reported public** (per our notes; please confirm in GitHub). It contains the supplier's name, address and phone, product lists, your personal email, the admin email and a map of the security design. For a business whose model is *not* showing restaurants the supplier, make it private.
- Test and seed scripts can run against the live database if someone has the live keys in their environment (the seed has a known admin password). Add guards.
- Invoice PDFs read the customer and company details live, so an old invoice changes if details are edited. Store a copy on the invoice.
- Region mismatch (see 2.7) also raises a UK-data-in-India question.
- No automatic checks before deploy: anything merged to `main` goes live.
- Supabase advisor, live: leaked-password protection off; 11 "security definer" views (these are the deliberate filtered views, accepted); 5 small helper functions callable by anyone but they only return the caller's own role. Migration 0010 settings are applied on live (I checked the values) but not recorded in the migration history table, a harmless drift.

**Low:** one-line open-redirect edge case on the `vercel.app` address, two staff submitting the same basket at once can place two orders, a few multi-step admin saves are not atomic, `http` extension still installed, no health endpoint, `framer-motion` used but not declared in package.json.

**Checked and good:** every server action and route checks the role and ownership; prices, costs and margins never reach a non-admin browser (HTML and hidden data scanned); orders are recomputed on the server and frozen with a price snapshot; driver links are single-use, hashed, expire in 72 h; uploads are checked by their bytes and stored privately; accessibility scan clean on 33 screens.
